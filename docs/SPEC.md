# 사투리 측정 서비스 개발 명세서

Nov 12, 2026 · @천정환

## 1. 개요

폰 브라우저에서 목소리를 녹음하면 사투리 권역과 농도를 판정해 감정서를 발급하는 모바일 웹 서비스다. 2026 컴퓨터학부 바보톤(주제: 쓸데없이 진지한 ○○) 출품작이며, 서비스 이름은 원산지증명서(프로젝트명 C/O)다.

| 항목 | 내용 |
| --- | --- |
| 형태 | 모바일 우선 웹, 설치와 회원가입 없음 |
| 팀 | 2명 (A: 판정 엔진, B: 화면과 경험) |
| 제작 기간 | 11/12(목) \~ 11/22(일) |
| 공개 투표 | 11/23(월) \~ 11/25(수), 이 기간 서버 유지 |

### 범위

| 구분 | 기능 | 완료 기준 |
| --- | --- | --- |
| 필수 | 권역 판정 | 서울경기, 강원, 충청, 경상, 전라, 제주 6개 권역의 확률 표시 |
| 필수 | 농도 측정 | 0\~100점과 5단계 등급, 근거 목록 표시 |
| 필수 | 감정서 | 이미지로 저장하고 공유 가능 |
| 확장 1 | 농도 랭킹 | 닉네임과 감정 결과로 등록, 상위 50명과 내 순위 표시. 음성은 저장하지 않는다(11/19 변경) |
| 확장 2 | 표준어 구사 능력 검정 | 판정 엔진 재사용, 새어 나온 사투리 적발 |
| 확장 3 | 지역 세분화 | 경북/경남, 전북/전남을 추가 질문으로 좁히기 |
| 추가 | 경상 정밀 감정 (11/20) | 별도 탭에서 경상 방언을 경북권(대구·경북)과 경남권(부산·울산·경남) 성분으로 나누고 신고 원산지와 대조해 정밀 감정서 발급. 정밀 감정 전용 랭킹(신고 원산지별 보기) (12장) |

자체 모델 학습, 네이티브 앱, 시·군 단위 판정, 로그인은 이번 대회에서 만들지 않는다. 경상 정밀 감정은 경북대(대구) 대회에 맞춰 확장 3의 경상 부분을 별도 탭과 별도 녹음으로 만든 것이다.

## 2. 사용자 흐름

접속부터 감정서 공유까지 7단계이며, 목표 소요 시간은 2분 이내다.

1. **접속**: 링크로 들어와 첫 화면에서 `감정 신청`을 누른다. 로그인은 없다.
2. **안내와 동의**: 마이크 권한을 요청한다. 녹음은 판정에만 쓰고 저장하지 않으며, 랭킹에 등록할 때만 닉네임과 감정 결과를 저장해 공개한다고 알린다.
3. **녹음**: 문항 6개를 순서대로 녹음한다. 주어진 문장 4개를 평소 말투로 바꿔 말한 다음, 상황극 2개에 자유롭게 답한다(8장). 문항당 10초, 합계 60초이고 처음부터 다시 녹음할 수 있다.
4. **심사 대기**: 판정이 끝날 때까지 심사 연출을 보여준다. 실제 대기 시간은 검증 단계에서 측정한다.
5. **결과**: 권역 확률, 농도 점수, 등급, 근거 목록을 보여준다.
6. **감정서**: 이미지로 저장하거나 공유한다.
7. **랭킹 등록(확장 1)**: 닉네임을 넣고 공개에 동의하면 농도 랭킹에 오른다. 공개되는 값은 닉네임, 농도, 지역, 등급, 등록 시각이고 음성은 저장하지 않는다. 등록하지 않으면 감정과 감정서만 이용한다.

경상 정밀 감정은 머리글의 `경상 정밀 감정` 탭, 첫 화면의 `경상 정밀 감정 받기` 버튼, 1순위 권역이 경상인 결과 화면의 권유 버튼으로 들어간다. 안내와 동의 → 원산지 신고 → 녹음 → 심사 → 정밀 결과 → 정밀 감정서 순서이며 12장에 있다. 정밀 감정 결과는 기존 랭킹과 따로 있는 정밀 감정 랭킹에 등록할 수 있고, 이때 닉네임, 신고 원산지, 경상 농도, 경북권 비율, 등록 시각이 공개된다.

## 3. AI 후보 조사와 선정

1순위는 Gemini 3.8 Flash에 오디오를 직접 넣어 한 번의 호출로 판정하는 방식이다. 억양 정보가 유지되고, 무료 등급으로 검증할 수 있으며, 판정 1회 비용이 약 0.01달러로 추정된다(9장). 최종 확정은 11/12\~13 검증 결과로 한다.

### 후보 비교

| 후보 | 종류 | 비용 (유료 등급, 100만 토큰당) | 판단 |
| --- | --- | --- | --- |
| [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models) (`gemini-3.8-flash`) | 오디오 입력 멀티모달 | 입력 $0.75, 출력 $3.75 (12/31까지, 이후 2배). 무료 등급 있음 | **1순위** |
| [Gemini 3.5 Flash-Lite](https://ai.google.dev/gemini-api/docs/models) (`gemini-3.5-flash-lite`) | 오디오 입력 멀티모달 | 입력 $0.30(오디오 포함), 출력 $2.50. 무료 등급 있음 | 비용 절감용 대안, 장애 시 대체 |
| [Gemini 4 Argon](https://ai.google.dev/gemini-api/docs/models) (`gemini-4-argon`) | 최상위 추론 모델 | 입력 $2, 출력 $10 (11/30까지, 12/1부터 2배). 무료 등급 없음 | 정확도 상한 확인용. 3.8 Flash와 차이가 크면 채택 검토 |

| [CLOVA Speech 단문 인식](https://api.ncloud-docs.com/docs/ai-application-service-clovaspeech-shortsentence) | 받아쓰기 전용 (한국어 특화) | 가격 미확인 | 60초 이내 파일만 받음. 방언 대응 여부 미확인 |
| [wav2vec-bert-korean-dialect-recognition](https://huggingface.co/HERIUN/wav2vec-bert-korean-dialect-recognition) | 방언 분류 전용 공개 모델 | 무료(MIT), GPU 서버 필요 | 6개 권역 평가 정확도 56.8%. 농도와 근거를 주지 못해 비교용으로만 |
| 자체 모델 학습 | AI Hub 방언 데이터로 파인튜닝 | GPU와 학습 시간 | 제외. 11일 일정에 맞지 않음 |

### 선정 근거

- **오디오 직접 입력**: 받아쓰기를 거치면 억양이 사라지고 사투리가 표준어로 고쳐질 수 있다. 멀티모달 모델은 소리를 그대로 듣는다.
- **한 번의 호출로 끝남**: 권역, 농도, 근거, 받아쓰기를 JSON 하나로 받는다. 구조화 출력 기능으로 형식을 고정한다.
- **Google 권장 모델**: Google은 신규 프로젝트에 3.8 Flash 또는 3.5 Flash-Lite를 쓰라고 안내한다. 2.5 계열은 기존 사용자에게만 열려 있다.
- **녹음 형식 호환**: Gemini 오디오 입력은 webm, mp4, m4a, mp3, wav 등을 받는다. 브라우저 녹음 파일을 변환 없이 보낼 수 있다. 다만 지원 목록에 audio/mp4가 없어, 아이폰 녹음은 파일을 그대로 두고 형식만 audio/m4a로 표시해 보낸다.

### 검증 계획 (11/12\~13)

같은 샘플 12개(5개 권역 2개씩과 표준어 2개)를 3.8 Flash, 3.5 Flash-Lite, Argon에 각각 3회씩 넣고 아래 기준으로 결정한다.

| 권역 정답률 (12개 중) | 결정 |
| --- | --- |
| 8개 이상 | 오디오 직접 판정으로 진행 |
| 5\~7개 | 유도 질문 비중을 늘려 사투리 표현을 끌어냄 |
| 4개 이하 | 받아쓰기 텍스트의 어휘와 어미 중심으로 전환, 억양 분석은 연출용으로만 |

정답률과 함께 근거의 진위(인용한 표현이 실제 녹음에 있는지), 같은 파일의 결과 일관성, 응답 시간을 기록한다.

## 4. 판정 파이프라인

녹음 파일 1개를 서버가 받아 Gemini에 한 번 호출하고, 점수 계산과 등급 매핑은 서버 코드가 한다. 모델에게는 관찰만 맡기고 최종 숫자는 코드로 계산해야 결과가 덜 흔들린다.

### 처리 순서

1. **클라이언트**: 문항 세트의 문항(기본 `set-b` 6개)을 한 번의 녹음 세션으로 이어 녹음한다(문항 사이는 일시정지). 파일 1개(문항당 10초, `set-b` 합계 60초)와 문항 세트 ID를 서버로 보낸다.
2. **서버 검사**: 파일 크기(2MB 이하), 형식, 호출 제한을 확인한다.
3. **AI 호출**: 오디오, 지시문, 문항 텍스트를 보내고 JSON 스키마로 출력 형식을 고정한다. 온도는 보내지 않는다(3.6 이후 모델은 이 값을 무시한다). 사고 수준을 medium으로 고정하고, 요청에 store: false를 넣어 Google 서버에 요청과 응답이 저장되지 않게 한다.
4. **후처리**: 권역 확률 합을 100으로 맞추고, 문항별 근거 검증, 판정 유보 확인(검증된 근거가 1순위 권역을 뒷받침하는지), 농도 계산(모사 의심이면 절반), 등급 매핑, 소견 문구 선택을 한다.
5. **응답**: 결과 JSON을 돌려주고 오디오는 버린다. 랭킹 등록에 쓸 농도, 1순위 권역, 등급과 등록 가능 여부(가짜 응답 결과인지, flags가 붙었는지, 판정 유보인지)만 감정 id로 Upstash Redis에 1시간 남긴다. 랭킹에 등록할 때 서버는 클라이언트가 보낸 점수 대신 이 기록을 쓴다. 기록에 실패해도 감정 결과는 그대로 돌려준다.

Gemini 문서에는 요청당 오디오 파일이 1개로 적혀 있어 녹음을 파일 하나로 만든다. 이 때문에 다시 녹음은 문항별이 아니라 처음부터 한다.

### 모델 지시문 (초안)

```
너는 한국어 방언 감정위원이다. 첨부한 음성은 화자가 아래 문항에 순서대로 답한 녹음이다.
녹음은 문항 순서대로 이어 붙인 것이고 문항 사이에 쉬는 구간이 없을 수 있다. 문항 경계가 불확실하면 내용으로 판단한다.

[문항 목록]
1. (바꿔 말하기) 너 어디야? 왜 이렇게 안 와? 언제 올 거야?
2. (바꿔 말하기) 너 왜 그래? 무슨 일 있어? 괜찮아?
3. (바꿔 말하기) 뭐라고? 잘 안 들려. 다시 말해 봐.
4. (바꿔 말하기) 아니야, 그게 아니고. 내 말 좀 들어 봐.
5. (상황 답하기) 오랜만에 고향 친구에게서 전화가 왔습니다. 받자마자 뭐라고 하시겠습니까?
6. (상황 답하기) 친구가 약속에 한 시간 늦게 와서는 웃고 있습니다. 한마디 해 주십시오.

규칙
1. 실제로 들린 것만 근거로 쓴다. 들리지 않은 표현을 지어내지 않는다.
2. transcript는 들린 발음 그대로 적는다. 표준어로 고치지 않는다. question_transcripts는 문항 순서대로 각 문항의 답을 같은 방식으로 적은 6개의 배열이다. 답하지 않은 문항은 빈 문자열로 둔다.
3. 문항 목록의 바꿔 말하기 문항은 화자가 주어진 표준어 문장을 자기 말투로 바꿔 말한 것이다. 주어진 문장과 달라진 부분(어미, 어휘, 발음)이 방언 근거다. 주어진 문장을 그대로 읽었으면 그 문항에서는 억양과 음운만 근거로 쓴다. 상황 답하기 문항은 주어진 상황에 맞게 자유롭게 답한 것이다.
4. evidence를 regions보다 먼저 정한다. 들린 방언 특징을 evidence에 모두 적고, 각 특징의 region에 그 특징이 가리키는 권역을 표시한다. 여러 권역에 공통인 특징이면 region은 common이다. 표준어에 가까운 서울경기 말씨의 특징도 들리면 seoul_gyeonggi로 적는다.
5. evidence의 question은 그 구절이 나온 문항 번호(1~6)이고, quote는 그 문항의 question_transcripts에 그대로 있는 구절이어야 한다.
6. regions는 evidence를 모두 적은 다음 그 근거를 종합해 정하는 여섯 권역의 확률이고 합은 100이다. 근거가 적거나 근거가 가리키는 권역이 엇갈리면 확률을 한 권역에 몰지 않는다. regions의 1순위는 common을 뺀 evidence가 가장 많이 가리키는 권역과 어긋나지 않아야 한다.
7. scores는 어휘, 어미, 음운, 억양 각각 0~100이고, regions 1순위 권역의 특징이 얼마나 나타나는지로 매긴다. 다른 권역의 특징은 점수에 넣지 않는다. 표준어와 차이가 없으면 0에 가깝게 준다.
8. imitation_suspected는 어휘와 어미가 가리키는 권역과 음운과 억양이 가리키는 권역이 다르면 true, 같으면 false다.
9. 말소리가 없거나 3초 미만이거나 주변 소음으로 판정할 수 없으면 audio_quality만 채운다. 이때 transcript, question_transcripts, evidence, regions, scores, imitation_suspected는 null로 둔다.
10. 욕설이나 혐오 표현이 들리면 flags에 profanity를, 실명이나 전화번호 같은 개인정보가 들리면 personal_info를 넣는다. 없으면 빈 배열로 둔다.
```

위는 기본 세트 `set-b`(8장)의 지시문 전문이다. 문항 수(6)와 문항 목록은 문항 세트에서 넣는다. 바꿔 말하기 문항이 섞인 세트는 문항 앞에 종류(바꿔 말하기, 상황 답하기)를 붙이고 규칙 3을 넣는다. 상황극만 있는 `set-a`는 종류를 붙이지 않고 규칙 3이 없어 규칙이 9개다. 문항 수(4)를 빼면 나머지 문구는 같고, `set-a` 지시문은 set-b를 넣기 전과 한 글자도 다르지 않다.

**바꿔 말하기 규칙** (11/21 추가). 바꿔 말하기 문항은 모든 화자가 같은 표준어 문장을 자기 말투로 바꿔 말한 것이므로, 주어진 문장과 달라진 부분(어미, 어휘, 발음)이 곧 방언 근거다. 문장을 그대로 읽었다면 어휘와 어미는 주어진 문장에서 온 것이므로 그 문항에서는 억양과 음운만 근거로 쓴다. 지시문에는 지역별 표현 예시를 넣지 않는다. 모델이 예시에 맞춰 듣거나 지어내지 않게 하기 위해서다.

**근거 먼저, 판정 나중** (11/21 변경). 전라 토박이 화자가 경상 95%로 판정된 일이 있었다. 권역 확률을 근거보다 먼저 쓰게 하면 모델이 첫인상으로 확률을 정한 뒤 근거를 거기에 맞추기 쉽다. 그래서 출력 순서를 받아쓰기(`transcript`, `question_transcripts`) → 근거(`evidence`) → 권역 확률(`regions`) → 항목 점수(`scores`) → 모사 의심(`imitation_suspected`)으로 바꾸고, JSON 스키마의 속성 순서와 지시문의 규칙 순서를 모두 여기에 맞췄다. 근거마다 그 특징이 가리키는 권역을 적게 하고, 권역 확률은 그 근거를 종합해 정하게 한다. 서버는 근거가 1순위 권역을 뒷받침하는지 다시 확인한다(아래 판정 유보). 표준어 화자는 방언 특징이 거의 들리지 않아 근거가 모자라기 쉬우므로, 서울경기 말씨의 특징도 들리면 근거로 적게 한다.

`audio_quality` 값은 `ok`, `too_short`, `no_speech`, `noisy` 넷 중 하나다. flags는 평소 비어 있고, 욕설이나 개인정보가 들리면 profanity, personal\_info 같은 값이 들어간다. 값이 있으면 랭킹 등록을 막는다.

예시는 `set-b` 6문항에 경상 방언으로 답한 가짜 응답(`src/lib/judge/mock.ts`)이다. 바꿔 말하기 문항(1\~4)의 근거는 주어진 문장과 달라진 부분이다. `set-a`로 되돌렸을 때 쓰는 4문항 가짜 응답도 같은 파일에 있다.

`question_transcripts`는 문항 순서대로의 받아쓰기이고 길이는 문항 수(`set-b` 6, `set-a` 4)다. 답하지 않은 문항은 빈 문자열이다. evidence의 `question`은 그 근거가 나온 문항 번호(1\~문항 수)다. JSON 스키마에서도 배열 길이(`minItems`, `maxItems`)와 문항 번호 범위(`minimum`, `maximum`)를 문항 수로 정한다. 그래도 모델이 문항별 받아쓰기를 문항 수만큼의 문자열로 주지 않으면 형식 오류로 실패시키지 않고, 전체 받아쓰기와 근거 목록으로 보여 준다(7장 `segments`는 빈 배열). 근거의 문항 번호가 1\~문항 수의 정수가 아니면 null로 읽는다.

evidence의 `region`은 그 특징이 가리키는 권역이다. 여섯 권역 키(`seoul_gyeonggi`, `gangwon`, `chungcheong`, `gyeongsang`, `jeolla`, `jeju`) 중 하나이고, 여러 권역에 공통인 특징이면 `common`이다. JSON 스키마도 이 일곱 값만 받는다. 그래도 값이 없거나 이 일곱 값이 아니면 형식 오류로 실패시키지 않고 null로 읽는다. `common`과 null인 근거는 판정 유보를 따질 때 어느 권역으로도 세지 않는다.

`scores`는 1순위 권역의 특징이 얼마나 나타나는지로 매기고, 다른 권역의 특징은 넣지 않는다. 다른 지역 사투리를 흉내 내면 어휘와 어미는 그 지역을 가리켜도 음운과 억양은 본래 말씨를 가리키기 쉽다. 그래서 `imitation_suspected`는 어휘와 어미가 가리키는 권역과 음운과 억양이 가리키는 권역이 다르면 true로 둔다. 값이 없거나 boolean이 아니면 형식 오류로 실패시키지 않고 false로 읽는다.

### 서버 후처리 규칙

| 항목 | 규칙 |
| --- | --- |
| 근거 검증 | `quote`가 그 근거의 문항(`question`) 받아쓰기에 없으면 그 근거를 버린다. 문항 번호가 없거나 범위 밖이어도 버린다. 문항별 받아쓰기가 없으면 전체 `transcript`에서 찾고 `question`은 null로 둔다. 비교할 때는 NFC로 맞추고 연속 공백을 한 칸으로 줄인다. 지어낸 근거를 걸러내는 장치다. |
| 문항별 받아쓰기 | 문항 번호, 문항 문구와 함께 `segments`로 내보낸다. 받아쓰기는 공백을 정리한다. 문항 수만큼 없으면 빈 배열이다. |
| 농도 점수 | 어휘 0.15, 어미 0.2, 음운 0.25, 억양 0.4의 가중 합을 반올림한다. 흉내 내기 쉬운 어휘와 어미보다 음운과 억양에 무게를 둔다(11/20 변경, 이전 0.2, 0.3, 0.2, 0.3). 가중치는 검증 결과로 조정한다. |
| 모사 의심 | `imitation_suspected`가 true면 농도 점수를 계산값의 절반으로 낮추고(0.5는 올림, 예: 57 → 29) 그 점수로 등급을 매긴다. 소견 끝에 '타 지역 방언 모사 의심.'을 붙이고, 응답의 `imitationSuspected`에 이 값을 넣는다. 랭킹에도 낮춘 점수가 올라간다. |
| 판정 지역 | 확률 1순위 권역. 1순위와 2순위 차이가 10 미만이면 '혼합 방언'으로 표기한다. 판정 유보면 그 대신 '판정 유보 (추정: ○○ 방언)'으로 표기한다(○○는 1순위 권역). |
| 판정 유보 | 근거 검증을 통과한 근거 중 1순위 권역을 가리키는 것이 2개 미만이거나, 다른 권역을 가리키는 것이 1순위 권역을 가리키는 것보다 많으면 `region.uncertain`을 true로 둔다. `region`이 `common`이거나 null인 근거는 어느 쪽에도 세지 않는다. 화면과 감정서는 판정 지역 자리에 '판정 유보 (추정: ○○ 방언)'을 쓰고 권역 확률 막대는 그대로 보여 준다. 농도, 등급, 소견은 바꾸지 않는다. 판정 유보 결과는 지역을 확정하지 못했으므로 랭킹에 등록할 수 없다(7장 403 `not_eligible`, `reason: "uncertain"`). 모델이 확률을 한 권역에 몰아도 근거가 따라오지 않으면 단정하지 않게 하는 장치다(11/21). |
| 품질 불량 | `audio_quality`가 `ok`가 아니면 결과 대신 재녹음 안내를 보낸다. |
| 소견 | 등급과, 네 항목 중 점수가 가장 높은 항목으로 문구 20개 중 하나를 고른다. 점수가 같으면 어휘, 어미, 음운, 억양 순으로 앞선 항목을 쓴다. 같은 녹음이면 같은 문구가 나온다. |

Next.js 프로젝트 하나에 화면과 서버 API를 함께 두고 Vercel에 배포한다. 저장소와 배포가 하나라 2명이 11일 안에 다루기 가장 단순하다.

브라우저는 서버하고만 통신한다. AI 호출과 DB 접근은 모두 서버가 하므로 API 키가 밖으로 나가지 않는다.

### 기술 스택

| 영역 | 선택 | 이유와 주의점 |
| --- | --- | --- |
| 프레임워크 | Next.js (App Router), TypeScript | 화면과 서버 API를 한 프로젝트로 관리 |
| 스타일 | Tailwind CSS | 모바일 화면을 빠르게 구성 |
| 녹음 | 브라우저 MediaRecorder API | 크롬은 webm, 아이폰 사파리는 mp4로 녹음된다. `isTypeSupported`로 형식을 고른다 |
| AI 호출 | Google Gen AI SDK, 서버에서만 호출 | API 키를 브라우저에 노출하지 않는다 |
| 배포 | Vercel Hobby | HTTPS 자동 적용(마이크 권한에 필수). 함수 요청 본문 한도 4.5MB |
| 호출 제한 | Upstash Redis (Vercel Marketplace) | KST 날짜별 감정 횟수(개인·전체)와 랭킹 등록 횟수(개인)를 센다. IP는 해시로만 쓰고, 키는 다음 날 0시(KST)에 만료 |
| 랭킹 저장 | Upstash Redis (호출 제한과 같은 DB) | 랭킹 항목과 1시간짜리 감정 기록(7장 데이터 모델). 음성을 저장하지 않으므로 Supabase와 파일 저장소는 쓰지 않는다(11/19 변경) |
| 감정서 이미지 | canvas, Web Share API | 감정서를 canvas에 직접 그려 PNG로 만든다. 공유 미지원 기기는 다운로드로 대체 |
| 파형 연출 | Web Audio API | 녹음 중 파형 표시. 판정에는 쓰지 않는 연출용 |

60초 녹음은 약 0.3\~1MB라 Vercel 본문 한도 안에 들어간다(화면은 48kbps로 녹음을 요청한다). 여유를 두고 서버에서 2MB로 제한한다.

### 개발 방식

- **저장소**: GitHub 저장소 1개. `main`에 올리면 Vercel이 자동 배포하고, PR마다 미리보기 주소가 생긴다.
- **계약 우선**: 첫날 7장의 응답 형식을 확정한다. B는 가짜 응답 파일로 화면을 만들고, A는 같은 형식을 내는 API를 만든다.
- **환경 변수**: `GEMINI_API_KEY`, `MOCK_AI`, `GEMINI_MODEL`, `GEMINI_FALLBACK_MODEL`, `GEMINI_THINKING_LEVEL`, Upstash 연결 값. Upstash는 Vercel Marketplace로 연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN`이 자동으로 들어간다. 직접 넣을 때는 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`을 쓰며, 둘 중 하나라도 있으면 이쪽을 먼저 쓴다. 읽기 전용 토큰(`KV_REST_API_READ_ONLY_TOKEN`)은 쓰지 않는다. 랭킹도 같은 Upstash 연결 값을 쓰고, 운영자가 랭킹 항목을 지울 때 쓰는 `ADMIN_TOKEN`(16자 이상)을 더한다. 저장소에 올리지 않고 Vercel 설정의 Production과 Preview에 모두 넣는다.
- **AI 도구 활용**: 대회 규정상 허용된다. 화면 초안과 반복 코드는 AI 도구로 만들고, 판정 지시문과 문항은 직접 검증한다.
- **기기 테스트**: 아이폰 사파리와 안드로이드 크롬 실기기에서 11/13까지 녹음과 업로드를 확인한다.

화면과 서버를 분리하는 방식(React와 Python 서버)은 음성 신호 분석 라이브러리가 필요할 때만 의미가 있어 채택하지 않는다.

## 6. 화면 명세

화면은 필수 6개와 확장 1개이며, 모두 폭 360\~430px 기준으로 만든다. 문체는 공공기관 민원 서류처럼 딱딱하게 통일한다. 머리글에는 `농도 랭킹 보기` 버튼을 두어 S7로 갈 수 있게 한다. 진행 중인 녹음이나 감정을 잃지 않도록 S3, S4에서는 이 버튼을 숨긴다.

머리글 아래에는 `일반 감정`과 `경상 정밀 감정` 탭을 둔다(11/20). 첫 화면(S1)에는 머리글이 없으므로 S1의 `경상 정밀 감정 받기` 버튼이 탭을 대신한다. 탭을 오가도 각 탭의 진행 상태는 그대로이고, 녹음과 심사 중에는 다른 탭으로 갈 수 없다. 머리글의 랭킹 버튼은 일반 감정 탭에서는 `농도 랭킹`(S7), 경상 정밀 감정 탭에서는 `정밀 랭킹`(정밀 감정 랭킹)을 연다. 정밀 감정 랭킹은 경상 정밀 감정 탭 안에서만 보인다. 로고를 누르면 일반 감정 첫 화면으로 돌아가고 정밀 감정의 진행 상태도 지운다. 정밀 감정 화면은 12장에 있다.

| 화면 | 구성 요소 | 동작 |
| --- | --- | --- |
| S1 첫 화면 | 기관풍 제목, 한 줄 소개, `감정 신청` 버튼, `농도 랭킹 보기` 버튼, `경상 정밀 감정 받기` 버튼 | `감정 신청`은 S2, `농도 랭킹 보기`는 감정 없이 S7로 이동. `경상 정밀 감정 받기`는 정밀 감정 탭을 연다(진행하던 정밀 감정이 있으면 그 단계, 없으면 안내) |
| S2 안내와 동의 | 절차 안내(문항 구성과 녹음 길이. `set-b`는 '바꿔 말하기 4문항, 상황극 2문항 구술 (총 60초)'), 녹음 처리 방식 고지(음성 미저장, 랭킹 등록 시에만 닉네임과 결과 저장), 동의 체크 | 동의 후 마이크 권한 요청. 거부하면 설정 방법 안내 |
| S3 녹음 | 문항 카드(문항 번호/문항 수, 문항 종류, 안내, 상황 문구 또는 바꿔 말할 문장 상자), `문항 N 녹음 시작 (10초)` 버튼, 남은 시간 막대, 파형, `다음 문항으로`(마지막 문항은 `녹음 완료 및 최종 제출`), `처음부터 다시` | `문항 N 녹음 시작 (10초)`을 눌러야 녹음이 이어지고 타이머가 흐른다. 10초가 지나거나 `다음 문항으로`를 누르면 타이머를 멈추고 녹음을 일시정지한 뒤 바로 다음 문항을 보여 준다. 이 대기 상태에서는 타이머가 10초에서 멈춰 있어 문항을 읽을 수 있다. 마지막 문항은 10초가 지나거나 `녹음 완료 및 최종 제출`을 누르면 바로 제출한다. 녹음은 일시정지와 이어 녹음으로 파일 1개를 만든다. `처음부터 다시`나 `첫 화면으로 나가기`를 누르면 녹음하던 파일을 제출하지 않는다. 바꿔 말하기 문항은 안내를 먼저 읽도록 ① 안내("아래 문장을 고향 친구에게 말하듯 평소 말투로 바꿔 말해 주십시오."와 그 아래 "글자 그대로 읽지 않으셔도 됩니다.")를 위에 크게, ② 바꿔 말할 문장을 그 아래 '바꿔 말할 문장' 표지를 단 인용 상자에 둔다. 바꿔 말하기 문항이 섞인 세트의 상황극 문항은 "이번에는 상황에 맞게 자유롭게 말해 주십시오"를 안내와 같은 크기로 보여 주고, 바꿔 말하기 다음 첫 상황극 문항(`set-b` 5번)은 "형식이 바뀝니다" 안내로 강조한다. 이런 세트는 새 문항이 나오면 문항 카드가 머리글에 가리지 않게 화면 위로 올린다. 휴대폰(폭 360\~430px, 높이 667px 이상)에서는 안내, 문장, 시작 버튼이 스크롤 없이 한 화면에 들어온다 |
| S4 심사 중 | 단계 문구(접수 완료, 음운 분석, 억양 대조, 감정위원 합의) | 응답이 오면 S5로 이동. 30초를 넘기면 재시도 안내 |
| S5 결과 | 판정 지역(판정 유보면 '판정 유보 (추정: ○○ 방언)'과, 유보 사유와 랭킹에 등록할 수 없다는 안내), 권역 확률 막대 6개, 농도 점수, 등급명, 문항별 카드(문항 문구, 그 문항의 받아쓰기, 그 문항의 근거. 바꿔 말하기 문항이 섞인 결과는 '바꿔 말하기 · 제시 문장' 또는 '상황 답하기'를 함께 적는다). 받아쓰기 안의 근거 인용 구절은 강조한다. 문항별 받아쓰기가 없으면(7장 `segments`가 빈 배열) 전체 받아쓰기와 근거 목록을 보여 준다. 1순위 권역이 경상이면(혼합 방언, 판정 유보 포함) 경상 정밀 감정을 권하는 `경상 정밀 감정 받기` 버튼 | `감정서 발급`은 S6, `랭킹 등록`은 S7(판정 유보면 버튼이 `농도 랭킹 보기`가 된다), `경상 정밀 감정 받기`는 정밀 감정 탭을 처음부터 연다 |
| S6 감정서 | 문서번호, 발급일, 판정 지역(판정 유보면 '판정 유보 (추정: ○○ 방언)'), 농도, 등급, 소견, 직인 | `이미지 저장`, `공유`, `농도 랭킹 등록`(S7, 판정 유보면 `농도 랭킹 보기`), `다시 감정받기` |
| S7 랭킹 (확장 1) | 내 감정 결과 요약(판정 지역 표기는 S5와 같다), 닉네임 입력, 공개 고지, 상위 50명, 내 순위(50위 밖이어도 표시). 감정 없이 들어오면 상위 50명만 보여 주고, 등록 영역 대신 "감정을 받으면 랭킹에 등록할 수 있습니다"와 `감정 신청` 버튼(S2)을 둔다. 판정 유보 결과로 들어오면 등록 영역 대신 "판정 유보 결과는 랭킹에 등록할 수 없습니다" 안내를 둔다 | `공개에 동의하고 랭킹 등록`을 눌러 등록한다. 닉네임은 2\~10자 한글·영문·숫자. 같은 결과는 감정 후 1시간 안에 한 번만 등록. 음성 재생, 신고, 본인 삭제는 없고 운영자가 지운다 |

### 오류 상태

| 상황 | 표시 문구 | 다음 행동 |
| --- | --- | --- |
| 말소리 없음, 너무 짧음 | 음성이 확인되지 않아 감정이 반려되었습니다 | 다시 녹음 |
| 주변 소음 | 소음으로 감정이 불가합니다. 조용한 곳에서 재신청 바랍니다 | 다시 녹음 |
| 호출 제한 초과 | 금일 감정 접수가 마감되었습니다 | 내일 다시 |
| 서버 오류 | 감정위원이 자리를 비웠습니다 | 재시도 버튼 |
| 경상 방언 미확인 (정밀 감정) | 경상 방언이 확인되지 않아 정밀 감정이 불가합니다 | 다시 녹음 또는 일반 감정 |

### 랭킹 공개 고지 (S7)

음성 공개 동의 체크는 음성을 저장하지 않게 바뀌면서 뺐다(11/19). 등록 버튼 바로 위에 아래 내용을 보여주고, `공개에 동의하고 랭킹 등록` 버튼을 누르는 것을 공개 동의로 본다.

- 등록하면 닉네임, 농도, 지역, 등급, 등록 시각이 랭킹에 공개됩니다.
- 음성과 받아쓰기는 저장하지 않으며, 기록은 대회 종료 후 1주 안에 모두 삭제합니다.
- 부적절한 닉네임은 운영자가 삭제할 수 있습니다.

등록하지 않아도 감정과 감정서 발급은 그대로 이용할 수 있다.

## 7. API 명세와 데이터 모델

API는 7개이고(그중 정밀 감정 랭킹 3개는 12장), 화면 개발은 아래 응답 형식을 계약으로 삼아 가짜 데이터로 먼저 진행한다. 랭킹은 음성 없이 닉네임과 농도만 다루도록 바꿨다(11/19). 음성 저장, 재생, 신고 API는 만들지 않는다.

| API | 용도 | 요청 | 성공 응답 |
| --- | --- | --- | --- |
| `POST /api/judge` | 감정 | multipart: `audio`(파일), `questionSetId`(`set-b` 일반 감정 기본, `set-a` 일반 감정 이전 구성, `set-gs` 경상 정밀 감정) | 200, 아래 결과 JSON. `set-gs`는 12장 정밀 감정 결과 JSON |
| `POST /api/ranking` | 랭킹 등록 (확장 1) | JSON: `{ "judgmentId": "j_…", "nickname": "…" }` | 201, `{ "entry": 랭킹 항목 }` |
| `GET /api/ranking?limit=50` | 랭킹 조회 (확장 1) | 선택: `id`(내 랭킹 항목 id) | 200, `{ "entries": [랭킹 항목], "total": 120, "me": 랭킹 항목 또는 null }` |
| `DELETE /api/ranking/{id}` | 운영자 삭제 (확장 1) | 헤더 `Authorization: Bearer <ADMIN_TOKEN>` | 204 |
| `POST /api/gyeongsang-ranking` | 정밀 감정 랭킹 등록 (12장) | JSON: `{ "judgmentId": "g_…", "nickname": "…", "origin": "daegu" }` | 201, `{ "entry": 정밀 랭킹 항목 }` |
| `GET /api/gyeongsang-ranking?area=all&limit=50` | 정밀 감정 랭킹 조회 (12장) | 선택: `area`(`all`, `gyeongbuk`, `gyeongnam`), `id`(내 정밀 랭킹 항목 id) | 200, `{ "area": "all", "entries": [정밀 랭킹 항목], "total": 12, "me": 정밀 랭킹 항목 또는 null }` |
| `DELETE /api/gyeongsang-ranking/{id}` | 정밀 감정 랭킹 운영자 삭제 (12장) | 헤더 `Authorization: Bearer <ADMIN_TOKEN>` | 204 |

예시의 농도 68은 4장 가중치로 계산한 값이다(40×0.15 + 85×0.2 + 60×0.25 + 75×0.4 = 6 + 17 + 15 + 30 = 68). id는 j\_ 뒤에 16진수 12자리이고, 문서번호의 숫자는 임의의 6자리다.

- `region.uncertain`은 판정 유보 여부다. 근거 검증을 통과한 근거 중 1순위 권역을 가리키는 것이 2개 미만이거나, 다른 권역을 가리키는 것이 더 많으면 true다(4장 서버 후처리 규칙). true면 S5 결과, S6 감정서와 PNG, S7의 내 결과 요약은 판정 지역 대신 '판정 유보 (추정: ○○ 방언)'(○○는 `region.top`의 권역 이름)으로 표시하고 권역 확률 막대는 그대로 보여 준다. `top`, `label`, `mixed`, `probabilities`는 유보와 상관없이 같은 규칙으로 채운다. 판정 유보 결과는 랭킹에 등록할 수 없다(403 `not_eligible`, `reason: "uncertain"`).
- `imitationSuspected`는 타 지역 방언 모사 의심(모델 판단)이다. true면 `intensity.score`는 계산값의 절반이고, 등급도 그 점수로 매기며, 소견 끝에 '타 지역 방언 모사 의심.'이 붙는다.
- `transcript`는 전체 받아쓰기이고, `segments`는 문항별 받아쓰기다. 둘 다 응답으로만 내려보내고 저장하지 않는다.
- `segments`의 `kind`는 문항 종류다. `convert`(바꿔 말하기)면 `prompt`는 바꿔 말할 표준어 문장이고, `question`(상황 답하기)이면 상황 문구다. `transcript`는 공백을 정리한 그 문항의 받아쓰기다. 답하지 않은 문항은 빈 문자열이다.
- 예시는 기본 세트 `set-b`(6문항)의 결과다. `set-a`로 녹음하면 `segments`는 4개이고 `kind`는 모두 `question`이다.
- `evidence`의 `question`은 근거가 나온 문항 번호이고, 근거는 그 문항의 받아쓰기로 검증한다. `region`은 그 근거가 가리키는 권역 키이고 여러 권역에 공통이면 `common`이며, 모델이 주지 않았거나 잘못된 값이면 null이다.
- 모델이 문항별 받아쓰기를 문항 수만큼 주지 않으면 `segments`는 빈 배열이다. 이때 근거는 전체 받아쓰기로 검증하고 `question`은 null이다.
- 화면(S5)은 `segments`가 있으면 문항별 카드(문항 문구, 그 문항의 받아쓰기, 그 문항의 근거)로 보여 주고, 받아쓰기 안의 근거 인용 구절을 강조한다. 없으면 전체 받아쓰기와 근거 목록으로 보여 준다.
- 화면 개발용 예시는 `mock/judge.json`이다. 가짜 응답(MOCK\_AI)을 실제 후처리한 결과와 같은지 테스트로 확인한다.

### 랭킹 항목 JSON

```json
{
  "rank": 1,
  "id": "r_3f9a0c1b2d4e",
  "nickname": "부산갈매기",
  "intensity": 92,
  "region": "gyeongsang",
  "grade": 5,
  "gradeName": "무형문화재 지정 검토 대상",
  "registeredAt": "2026-11-23T14:03:00+09:00"
}
```

- 순위는 농도가 높은 순이고, 농도가 같으면 먼저 등록한 항목이 앞선다. `rank`와 `gradeName`은 저장하지 않고 읽을 때 붙인다.
- `region`은 감정 결과의 1순위 권역(`region.top`)이다. 혼합 방언이어도 1순위 권역을 쓴다. 판정 유보 결과는 등록할 수 없다(403).
- 등록할 때 서버는 감정할 때 남긴 농도, 지역, 등급을 쓰고 요청 본문의 점수는 무시한다. 감정 후 1시간이 지나면 등록할 수 없다(404).
- 감정 1건당 한 번만 등록된다(409). 닉네임은 앞뒤 공백을 떼고 2\~10자의 한글, 영문, 숫자만 받는다.
- 가짜 응답 모드(`MOCK_AI=true`)로 받은 결과와, 서버가 가짜 응답 모드일 때의 등록 요청은 받지 않는다(403).
- `limit`은 1\~50이고 없으면 50이다. `id`를 주면 그 항목이 50위 밖이어도 `me`에 순위와 함께 돌려준다. 등록 직후 화면은 POST 응답의 `entry.id`로 내 순위를 조회한다.
- 항목 id는 r\_ 뒤에 16진수 12자리다. 운영자는 조회 응답에서 id를 찾아 삭제한다.

### 데이터 모델 (Upstash Redis)

Supabase 대신 호출 제한과 같은 Upstash Redis에 저장한다(11/19 변경). 음성, 받아쓰기, IP 원문은 어디에도 저장하지 않는다.

| 키 | 값 | 만료 |
| --- | --- | --- |
| `co:judgment:{감정 id}` | 농도, 1순위 권역, 등급, 가짜 응답 여부, flags 여부, 판정 유보 여부(JSON). 감정에 성공하면 저장 | 1시간 |
| `co:judgment:{감정 id}:ranked` | 등록한 랭킹 항목 id. 감정 1건당 1회 등록을 보장한다(SET NX) | 1시간 |
| `co:ranking:entries` (해시) | 랭킹 항목 id → 닉네임, 농도, 지역, 등급, 등록 시각(JSON) | 없음. 대회 후 직접 삭제 |
| `co:ranking` (정렬 집합) | 랭킹 항목 id. 점수는 농도 순, 같으면 먼저 등록한 순 | 없음. 대회 후 직접 삭제 |

| `co:ranking:{KST 날짜}:ip:{IP 해시}`, `co:ranking:{KST 날짜}:global` | 랭킹 등록 횟수. 농도 랭킹과 정밀 감정 랭킹 등록을 합쳐 센다. 전체 횟수는 세기만 하고 막지 않는다 | 다음 날 0시(KST) |

| `co:gs:ranking:entries` (해시), `co:gs:ranking`, `co:gs:ranking:gyeongbuk`, `co:gs:ranking:gyeongnam` (정렬 집합) | 정밀 감정 랭킹 항목과 전체, 대구·경북, 부산·울산·경남 보기(12장) | 없음. 대회 후 직접 삭제 |

등록 표시와 항목 저장, 정렬 집합 추가는 Lua 스크립트 하나로 처리해 동시에 두 번 눌러도 한 번만 등록된다. 호출 제한도 개인과 전체 횟수를 Lua 스크립트 하나로 확인하고 센다. 개인 키에는 IP 원문 대신 해시(HMAC)를 쓴다.

Upstash가 없는 로컬 개발에서는 같은 구조를 프로세스 메모리로 대신한다. Production에서 Upstash 설정이 없으면 감정과 랭킹 API는 모두 500을 돌려준다. 가짜 응답 모드는 예외로, 호출 제한 없이 감정하고 랭킹은 인스턴스 메모리를 쓴다(등록은 403).

## 8. 녹음 문항 설계

일반 감정의 기본 문항 세트는 `set-b`다(11/21 변경). 문항은 6개이고 문항마다 10초씩 답을 녹음해, 합친 60초를 분석한다. 앞의 4문항은 화면에 나온 표준어 문장을 고향 친구에게 말하듯 평소 말투로 바꿔 말하는 문항(바꿔 말하기, `convert`)이고, 뒤의 2문항은 상황에 맞게 자유롭게 답하는 상황극(상황 답하기, `question`)이다.

바꿔 말하기는 모든 화자가 같은 문장을 말하므로, 주어진 표준어 문장과 달라진 어미, 어휘, 발음을 근거로 바로 대조할 수 있다(4장 규칙 3). 문장을 글자 그대로 읽으면 사투리가 줄어드는 문제는 두 가지로 줄인다. 화면에 "글자 그대로 읽지 않으셔도 됩니다"를 함께 보여 주고, 그대로 읽은 문항은 억양과 음운만 근거로 쓰게 한다. 뒤의 상황극 2문항은 친한 사람에게 감정을 실어 말하는 자연스러운 말투를 끌어낸다.

### 기본 구성 (`set-b`)

| 문항 | 종류 | 상대 | 화면 문구 | 노리는 단서 |
| --- | --- | --- | --- | --- |
| Q1 | 바꿔 말하기 | 고향 친구 | 너 어디야? 왜 이렇게 안 와? 언제 올 거야? | 의문사가 있는 물음(어디, 왜, 언제)의 어미와 억양 |
| Q2 | 바꿔 말하기 | 고향 친구 | 너 왜 그래? 무슨 일 있어? 괜찮아? | 의문사가 있는 물음과 예·아니오 물음의 어미 차이, 걱정하는 억양 |
| Q3 | 바꿔 말하기 | 고향 친구 | 뭐라고? 잘 안 들려. 다시 말해 봐. | 되묻는 말과 시키는 말의 어미, 발음 |
| Q4 | 바꿔 말하기 | 고향 친구 | 아니야, 그게 아니고. 내 말 좀 들어 봐. | 부정하는 말, 지시어, 시키는 말의 어미 |
| Q5 | 상황 답하기 | 고향 친구 | 오랜만에 고향 친구에게서 전화가 왔습니다. 받자마자 뭐라고 하시겠습니까? | 묻는 말의 어미와 억양, 안부 표현 |
| Q6 | 상황 답하기 | 친구 | 친구가 약속에 한 시간 늦게 와서는 웃고 있습니다. 한마디 해 주십시오. | 따지고 강조하는 표현, 감정이 실린 억양 |

### 화면 안내

- 바꿔 말하기 문항은 읽는 순서를 두 단계로 나눈다(11/21 변경). 큰 문장만 보고 그대로 읽는 일을 줄이려고, 안내를 먼저 읽고 문장을 말하게 한다.
  - ① 안내(위, 크게 굵게): "아래 문장을 고향 친구에게 말하듯 평소 말투로 바꿔 말해 주십시오." 그 아래 한 줄: "글자 그대로 읽지 않으셔도 됩니다."
  - ② 문장(아래): "바꿔 말할 문장" 표지를 단 인용 상자에 따옴표로 감싸 넣는다. 배경과 테두리로 안내와 구분하고, 글자는 안내보다 작지 않게 한다.
- 상황극 문항은 상황 문장이 곧 안내이므로 상황 문장을 크게 둔다. 바꿔 말하기가 섞인 세트는 "이번에는 상황에 맞게 자유롭게 말해 주십시오"를 바꿔 말하기 안내와 같은 크기로 보여 주고, 4번에서 5번으로 넘어갈 때는 문항 카드 맨 위에 "형식이 바뀝니다" 안내를 강조한다. 이 세트의 상황극 문항은 상황 문장에 대화 상대가 나오므로 '대화 상대' 줄을 따로 두지 않는다.
- 안내 글자는 휴대폰에서 18px(text-lg) 이상, 굵게, 흰색에 가깝게 한다. 문항 번호 옆에 문항 종류(바꿔 말하기, 상황극 녹음)를 적고, "설명하지 마시고, 실제로 그 사람에게 말하듯이 답변해 주십시오"를 14px로 함께 보여 준다(휴대폰은 버튼 아래, 넓은 화면은 문항 카드 아래).
- 휴대폰(폭 360\~430px, 높이 667px 이상)에서는 안내, 문장, 녹음 시작 버튼이 스크롤 없이 한 화면에 들어오게 여백과 파형을 줄인다. 앞 화면의 스크롤이 남아 문항 카드 윗부분이 머리글에 가릴 수 있으므로, 새 문항이 나오면 문항 카드를 머리글 바로 아래로 올린다. 녹음 시작 버튼을 눌러야 타이머가 흐르는 점은 그대로다.

### 이전 구성 (`set-a`)

`set-b` 전의 기본 세트로, 상황극 4문항, 합계 40초다. 지우지 않고 남겨 둔다. 환경 변수 `NEXT_PUBLIC_QUESTION_SET=set-a`로 빌드하면 화면이 이 세트로 녹음하고 `questionSetId=set-a`로 보낸다. 이 값은 빌드할 때 화면 코드에 들어가므로 바꾼 뒤에는 다시 배포해야 한다. 서버는 두 세트를 모두 받는다.

| 문항 | 상대 | 화면 문구 | 노리는 단서 |
| --- | --- | --- | --- |
| Q1 | 고향 친구 | 오랜만에 고향 친구에게서 전화가 왔습니다. 받자마자 뭐라고 하시겠습니까? | 묻는 말의 어미와 억양, 안부 표현 |
| Q2 | 친구 | 친구가 약속에 한 시간 늦게 와서는 웃고 있습니다. 한마디 해 주십시오. | 따지고 강조하는 표현, 감정이 실린 억양 |
| Q3 | 동생 | 동생이 한겨울에 반팔만 입고 나가려 합니다. 말려 보십시오. | 시키거나 말리는 말의 어미 |
| Q4 | 할머니 | 할머니가 차려 주신 밥이 정말 맛있습니다. 할머니께 뭐라고 하시겠습니까? | 어른께 쓰는 높임 어미, 감탄 표현 |

네 문항은 서로 다른 말하기 형태(묻는 말, 따지는 말, 시키는 말, 어른께 하는 말)를 끌어내도록 골랐고, 모두 가까운 사람에게 말하는 상황극이다. `set-b`의 상황극 2문항은 이 가운데 Q1과 Q2다.

### 운영 규칙

- 문항 수만큼 문항당 10초씩 녹음한다. 10초가 지나면 그 문항의 녹음을 멈추고 다음 문항을 보여 준다.
- 이 문항은 초안이다. 검증에서 사투리가 잘 나오지 않거나 10초 안에 답하기 어려운 문항은 교체한다. 바꿔 말하기 문항을 글자 그대로 읽는 비율도 검증에서 확인한다.
- 문항 세트는 `questionSetId`로 구분한다. 일반 감정은 `set-b`(기본)와 `set-a`(이전 구성), 경상 정밀 감정은 `set-gs`(12장)다. 일반 감정 문항은 `src/lib/judge/questions.ts` 한 파일에 있고 녹음 화면(S3)과 지시문(4장)이 함께 쓴다.
- 답변 예시는 보여 주지 않는다. 특정 지역 사투리 예시를 보여 주면 사용자가 따라 말해 판정과 근거가 오염된다.

### 확장 기능의 문항

| 확장 | 문항 방식 |
| --- | --- |
| 표준어 구사 능력 검정 | "뉴스 진행자처럼 표준어로 읽어 주십시오"와 낭독 문장 3개. 검출된 사투리 근거를 '적발 건수'로 표시 |
| 지역 세분화 | 권역 판정 뒤 추가 질문 2\~3개. 예: 특정 어미를 쓰는지, 특정 음식을 뭐라고 부르는지. 음성과 선택형 답을 함께 사용 |
| 경상 정밀 감정 | 문항 세트 `set-gs`의 4문항, 문항당 10초. 문구는 `src/lib/gyeongsang/questions.ts` 한 파일에 있고 지금은 임시 문구다(12장) |

## 9. 비용, 호출 제한, 개인정보

감정 1회 비용은 약 0.01달러로 추정되며, 하루 1,500회 상한을 두면 하루 최대 약 15달러다. 공개 서비스는 Gemini 유료 등급으로 운영한다. 무료 등급은 보낸 내용이 Google 제품 개선에 쓰이기 때문이다.

### 감정 1회 비용 추정 (Gemini 3.8 Flash, 12/31까지 가격)

| 구분 | 토큰 수 (추정) | 단가 (100만 토큰당) | 비용 |
| --- | --- | --- | --- |
| 입력: 60초 오디오와 지시문 | 약 3,000 | $0.75 | 약 $0.0023 |
| 출력: 결과 JSON과 사고 토큰 | 약 2,000 | $3.75 | 약 $0.0075 |
| 합계 |  |  | 약 $0.01 |

오디오는 초당 25\~32토큰으로 계산했다(60초면 1,500\~1,920토큰). 녹음이 40초(`set-a`)에서 60초(`set-b`)로 늘어 오디오 입력이 500\~640토큰 늘고 지시문도 조금 길어졌지만, 감정 1회 비용은 여전히 약 0.01달러다. 사고 토큰 양에 따라 출력 비용이 달라지므로, 검증 때 실제 사용량을 확인해 이 표를 고친다. 감정 2,000회면 약 20달러, 5,000회면 약 50달러다.

### 결제와 등급

| 등급 | 조건 | 데이터 사용 | 용도 |
| --- | --- | --- | --- |
| 무료 | 카드 불필요. 요청 한도는 AI Studio에서 프로젝트별로 확인 | Google 제품 개선에 사용됨 | 팀원 본인 목소리로 하는 개발과 검증 |

무료용과 유료용 프로젝트를 따로 만들어 키를 분리한다. 선불 잔액이 0이 되면 호출이 멈추므로 투표 기간에는 잔액을 매일 확인한다.

### 호출 제한

| 제한 | 값 | 초과 시 |
| --- | --- | --- |
| 개인 (IP 해시 기준) | 하루 60회. 교내 와이파이처럼 여러 사람이 IP 하나를 함께 쓰는 경우를 고려한다. 일반 감정과 경상 정밀 감정을 합쳐 센다 | 429, 접수 마감 문구 |
| 전체 | 하루 1,500회. 일반 감정과 경상 정밀 감정을 합쳐 센다 | 429, 접수 마감 문구 |

### 개인정보 처리

- **음성은 어느 경우에도 저장하지 않는다.** 서버 메모리에서 AI로 전달한 뒤 버린다. 랭킹에 등록해도 음성은 저장하거나 공개하지 않는다(11/19 변경).
- 받아쓰기 결과도 저장하지 않는다. 응답으로 한 번 내려보낼 뿐이다.
- 감정할 때는 랭킹 등록 자격(농도, 1순위 권역, 등급, 가짜 응답 여부, flags 여부, 판정 유보 여부)만 감정 id로 1시간 저장한다. 경상 정밀 감정은 정밀 감정 랭킹 등록 자격(경상 농도, 경북권 비율, 가짜 응답 여부, flags 여부)만 1시간 저장한다.
- 경상 정밀 감정의 신고 원산지는 감정할 때 서버로 보내지 않는다. 정밀 감정 랭킹에 등록할 때만 보내고 랭킹 항목에 저장한다. 등록하지 않으면 정밀 결과 화면과 정밀 감정서에만 쓴다.
- **랭킹 공개 동의는 등록 시점에 받는다.** 등록하면 닉네임, 농도, 지역, 등급, 등록 시각을 저장하고 랭킹에 공개한다. 정밀 감정 랭킹은 닉네임, 신고 원산지, 경상 농도, 경북권 비율, 등록 시각을 저장하고 공개한다. 공개 고지는 6장과 12장에 있다.
- IP 원문은 저장하지 않는다. 호출 제한용 IP 해시는 다음 날 0시(KST)에 지워진다.
- 본인이 직접 지우는 기능은 없다. 삭제 요청은 운영자가 받아 `DELETE /api/ranking/{id}`로 지운다. 대회 종료 후 1주 이내에 랭킹 데이터를 전부 삭제한다.
- S2 화면에 다음을 고지한다: 음성이 판정을 위해 Google의 AI 서비스로 전송된다는 점, 음성을 저장하지 않는다는 점, 랭킹에 등록하면 닉네임과 결과가 공개된다는 점, 정밀 감정 랭킹은 신고 원산지와 경북권 비율도 저장한다는 점.

### 랭킹 저장 용량

음성을 저장하지 않으므로 항목 1건은 수백 바이트이고 용량은 문제가 되지 않는다. Upstash 무료 한도는 명령 수와 용량 기준이므로 투표 기간에는 콘솔에서 사용량을 확인한다. 서버가 보내는 Redis 명령은 랭킹 조회 1회에 2\~5개, 등록 1회에 3개(Lua 스크립트 2개 포함), 감정 1회에 2개(Lua 스크립트 1개 포함)다. 정밀 감정과 정밀 감정 랭킹도 같다.

## 12. 경상 정밀 감정

경북대(대구) 대회에 맞춰 경상 방언 전용 감정을 별도 탭으로 추가했다(11/20). 경상 방언을 경북권(대구·경북)과 경남권(부산·울산·경남) 성분으로 나누고, 사용자가 신고한 원산지와 대조해 정밀 감정서를 발급한다. 일반 감정, S1\~S7 화면의 동작, 기존 랭킹과 저장 데이터는 바꾸지 않는다. 정밀 감정 결과는 기존 랭킹과 따로 있는 정밀 감정 랭킹에 등록할 수 있다(아래 절).

### 진입과 흐름

머리글의 `경상 정밀 감정` 탭, S1의 `경상 정밀 감정 받기` 버튼, 1순위 권역이 경상인 S5의 `경상 정밀 감정 받기` 버튼으로 들어간다. 탭과 S1의 버튼은 진행하던 정밀 감정이 있으면 그 단계를, 없으면 안내를 보여 준다(S1에는 머리글이 없어 버튼이 탭을 대신한다). S5의 버튼은 새 감정 결과를 받은 뒤의 권유이므로 정밀 감정을 처음(안내)부터 시작한다.

| 단계 | 화면 | 구성 요소와 동작 |
| --- | --- | --- |
| 1 | 안내와 동의 | S2를 그대로 쓴다. `이전 화면으로`는 일반 감정 탭으로 돌아간다 |
| 2 | 원산지 신고 | 대구, 경북(경북권)과 부산, 울산, 경남(경남권) 중 하나를 고른다. 일치 판정 기준과, 신고 원산지는 정밀 랭킹에 등록할 때만 서버에 저장한다는 안내. 고르기 전에는 다음으로 갈 수 없다 |
| 3 | 녹음 | S3에 `set-gs` 문항을 넘겨 쓴다. 동작은 S3와 같다. `처음부터 다시`는 녹음을 다시 하고, `첫 화면으로 나가기`는 정밀 감정 안내로 돌아간다 |
| 4 | 심사 | S4를 `questionSetId=set-gs`와 정밀 감정 단계 문구로 쓴다. 오류 처리는 S4와 같다. 경상 방언 미확인이면 "경상 방언이 확인되지 않아 정밀 감정이 불가합니다"를 보여 주고, `처음부터 다시 녹음하기`는 정밀 감정 안내로 돌아간다 |
| 5 | 정밀 결과 | 신고 원산지와 일치 여부, 감정 성분 막대(경북권·경남권), 경상 농도와 등급, 항목 점수, 문항별 받아쓰기와 근거(인용 구절 강조). `정밀 감정서 발급`, `정밀 랭킹 등록`, `다시 정밀 감정받기` |
| 6 | 정밀 감정서 | 아래 정밀 감정서 절. `이미지 저장`, `공유`, `정밀 랭킹 등록`, `다시 정밀 감정받기` |

모든 단계 위에 정밀 감정 띠(단계 번호, 진행 막대, 신고 원산지)를 둔다. 머리글의 단계 표시는 안내, 원산지 신고, 녹음, 분석 중(오류면 분석 중단), 정밀 결과, 정밀 감정서다.

### 문항 (`set-gs`)

문항은 4개이고 문항당 10초다. 문구는 `src/lib/gyeongsang/questions.ts` 한 파일에 모았고, 녹음 화면과 지시문이 이 파일을 함께 쓴다. 지금 문구는 임시 문구이며 확정 문구는 이 파일만 고치면 된다. 일반 감정 문항과 같은 이유로 답변 예시는 보여 주지 않는다(8장).

### 모델 지시문

```
너는 경상 방언 정밀 감정위원이다. 첨부한 음성은 화자가 아래 문항에 순서대로 답한 녹음이다.
이 감정은 화자의 경상 방언이 경북권(대구·경북)과 경남권(부산·울산·경남) 중 어느 쪽의 특징을 얼마나 띠는지와 경상 방언의 농도를 가린다.
녹음은 문항 순서대로 이어 붙인 것이고 문항 사이에 쉬는 구간이 없을 수 있다. 문항 경계가 불확실하면 내용으로 판단한다.

[문항 목록]

규칙
1. 실제로 들린 것만 근거로 쓴다. 들리지 않은 표현을 지어내지 않는다. 미리 아는 표현 목록에 맞추지 말고 이 녹음에서 들린 어휘, 어미, 음운, 억양으로만 판단한다.
2. transcript는 들린 발음 그대로 적는다. 표준어로 고치지 않는다. question_transcripts는 문항 순서대로 각 문항의 답을 같은 방식으로 적은 4개의 배열이다. 답하지 않은 문항은 빈 문자열로 둔다.
3. not_gyeongsang은 경상 방언의 특징이 들리지 않거나 다른 지역 방언으로 들려 경상 방언으로 보기 어려우면 true, 경상 방언의 특징이 들리면 false다. true면 subregions, scores, evidence는 null로 둔다.
4. subregions는 들린 경상 방언의 특징이 경북권(대구·경북)과 경남권(부산·울산·경남) 중 어느 쪽에 가까운지의 비율이고 합은 100이다.
5. scores는 어휘, 어미, 음운, 억양 각각 0~100이고, 경상 방언의 특징이 얼마나 나타나는지로 매긴다. 다른 지역 방언의 특징은 점수에 넣지 않는다. 표준어와 차이가 없으면 0에 가깝게 준다.
6. evidence의 question은 그 구절이 나온 문항 번호(1~4)이고, quote는 그 문항의 question_transcripts에 그대로 있는 구절이어야 한다. note에는 그 구절이 어떤 경상 방언 특징인지와 경북권, 경남권 중 어느 쪽에 가까운지를 적는다.
7. 말소리가 없거나 3초 미만이거나 주변 소음으로 판정할 수 없으면 audio_quality만 채운다. 이때 transcript, question_transcripts, not_gyeongsang, subregions, scores, evidence는 null로 둔다.
8. 욕설이나 혐오 표현이 들리면 flags에 profanity를, 실명이나 전화번호 같은 개인정보가 들리면 personal_info를 넣는다. 없으면 빈 배열로 둔다.
```

문항 수(4)와 문항 목록은 `set-gs`에서 넣는다. 일반 감정 지시문(4장)과 달리 특정 방언 표현의 목록이나 예시를 넣지 않는다. 모델이 목록에 맞춰 듣거나 지어내지 않고 이 녹음에서 들린 것만 근거로 쓰게 하기 위해서다. 사용자 입력 문장은 일반 감정과 같다.

### 서버 처리

`POST /api/judge`가 `questionSetId=set-gs`를 받으면 일반 감정 대신 정밀 감정 파이프라인(`src/lib/gyeongsang/pipeline.ts`)으로 보낸다. 일반 감정의 처리 경로와 응답 형식은 그대로다.

| 항목 | 규칙 |
| --- | --- |
| 서버 검사 | 파일 크기(2MB)와 형식. 일반 감정과 같다 |
| 호출 제한 | 일반 감정과 같은 키로 센다. IP당 하루 60회와 전체 1,500회는 두 감정을 합친 횟수다 |
| AI 호출 | 주 모델이 실패하거나 형식 오류면 대체 모델로 1회 재시도. 첫 시도 20초, 합계 25초. 일반 감정과 같은 함수를 쓴다 |
| 반려 | `audio_quality`가 `ok`가 아니면 422와 그 사유, `not_gyeongsang`이 true면 422 `not_gyeongsang` |
| 성분 비율 | 합을 100으로 맞춘다. 최대 잔여법을 쓰고, 나머지가 같으면 경북권에 1을 더 준다 |
| 근거 검증 | 일반 감정과 같다. 인용이 그 문항의 받아쓰기에 없으면 버린다 |
| 농도와 등급 | 경상 방언 특징 기준의 항목 점수에 4장 가중치(어휘 0.15, 어미 0.2, 음운 0.25, 억양 0.4)를 매기고 4장 등급표를 쓴다. 모사 의심과 소견은 없다 |
| 저장 | 정밀 감정 랭킹 등록 자격(경상 농도, 경북권 비율, 가짜 응답 여부, flags 여부)만 정밀 감정 id로 1시간 남긴다. 신고 원산지와 받아쓰기는 남기지 않는다 |

### 원산지 일치 판정

신고 원산지가 속한 성분의 비율이 50 이상이면 `원산지 일치`, 아니면 `원산지 불일치, 재심 권고`다. 감정할 때 서버는 신고 원산지를 받지 않으므로 화면에서 판정한다. 정밀 감정 랭킹은 등록한 신고 원산지와 경북권 비율로 같은 규칙을 계산해 `matched`로 돌려준다.

| 신고 원산지 | 보는 성분 | 원산지 일치 |
| --- | --- | --- |
| 대구, 경북 | 경북권 | 경북권 50 이상 |
| 부산, 울산, 경남 | 경남권 | 경남권 50 이상 |

두 성분이 50씩이면 어느 원산지를 신고해도 일치다.

### 정밀 감정 결과 JSON

```json
{
  "id": "g_5c1e0a9b7d23",
  "certificateNo": "제2026-경상-000123호",
  "issuedAt": "2026-11-20T14:03:00+09:00",
  "subregions": { "gyeongbuk": 64, "gyeongnam": 36 },
  "intensity": {
    "score": 69,
    "grade": 4,
    "gradeName": "자막 필요",
    "parts": { "vocabulary": 55, "endings": 80, "phonology": 65, "intonation": 70 }
  },
  "evidence": [
    { "question": 1, "quote": "갈 끼라", "note": "'갈 거야'를 뜻하는 경상 방언 종결 표현" }
  ],
  "transcript": "엄마 내 지금 학교 앞이다, 금방 갈 끼라 니 내 과자 다 묵었나? 와 말도 없이 다 무뿟노 야 그거 무겁제? 이리 도, 내가 들어 주께 아지매 이 사과 얼만교? 쪼매만 깎아 주이소",
  "segments": [
    { "question": 1, "prompt": "어머니께서 전화로 언제 집에 오느냐고 물으십니다. 대답해 드리십시오.", "transcript": "엄마 내 지금 학교 앞이다, 금방 갈 끼라" }
  ]
}
```

- 예시의 농도 69는 55×0.15 + 80×0.2 + 65×0.25 + 70×0.4 = 68.5를 반올림한 값이다. `segments`는 일부만 적었다.
- id는 g\_ 뒤에 16진수 12자리다. 일반 감정 id(j\_)와 달라 기존 랭킹에는 등록할 수 없고, 정밀 감정 랭킹에 이 id로 등록한다. 문서번호는 `제{발급 연도}-경상-{6자리}호`이고 숫자는 임의다.
- 일반 감정 결과의 `region`, `imitationSuspected`, `opinion`은 없다. `transcript`, `segments`, `evidence`의 `question`은 일반 감정과 같은 규칙이고 저장하지 않는다.

### 정밀 감정서

제목은 `경상 방언 정밀 감정서`이고 문서번호, 발급일, 신고 원산지와 그 성분, 감정 성분 막대, 일치 여부 도장, 경상 농도, 등급, 발급 기관과 직인을 담는다. 일반 감정서(S6)와 구분되도록 한지 색 바탕, 적갈색 머리띠, 이중 테두리와 모서리 장식, 비스듬한 일치 여부 도장, 네모난 직인을 쓴다. 이미지는 1200×1600 PNG이고 파일 이름은 `{문서번호}-정밀감정서.png`다. 공유는 S6와 같이 Web Share로 파일을 보내고, 지원하지 않는 기기에서는 이미지로 저장한다.

### 정밀 감정 랭킹

기존 농도 랭킹과 다른 Redis 키(`co:gs:*`)와 다른 API(`/api/gyeongsang-ranking`)를 쓰는 별도 랭킹이다. 기존 랭킹 API와 저장 데이터는 건드리지 않는다. 경상 정밀 감정 탭 안에서만 보인다(정밀 결과와 정밀 감정서의 `정밀 랭킹 등록`, 정밀 감정 탭 머리글의 `정밀 랭킹`).

| 항목 | 규칙 |
| --- | --- |
| 저장하는 값 | 닉네임, 신고 원산지, 경상 농도, 경북권 비율, 등록 시각(과 항목 id). 등급과 원산지 일치 여부는 읽을 때 계산한다 |
| 보기 | 전체, 대구·경북, 부산·울산·경남. 나누는 기준은 AI 판정이 아니라 신고 원산지다(대구, 경북은 대구·경북, 부산, 울산, 경남은 부산·울산·경남) |
| 순위 | 경상 농도가 높은 순, 같으면 먼저 등록한 순. 보기마다 상위 50명과 그 보기의 인원수, 내 순위(50위 밖이어도)를 보여 준다. 다른 보기의 항목은 내 순위로 보이지 않는다 |
| 점수 위조 방지 | 정밀 감정할 때 서버가 남긴 경상 농도와 경북권 비율(1시간)만 쓰고 요청의 점수는 무시한다. 신고 원산지는 사용자가 고른 값이라 등록 요청으로 받는다(`daegu`, `gyeongbuk`, `busan`, `ulsan`, `gyeongnam`) |
| 기존 랭킹과 같은 규칙 | 감정 1건당 1회(409), 감정 후 1시간 안(404), 닉네임 2\~10자 한글·영문·숫자(400), 가짜 응답 결과와 flags가 붙은 결과는 등록 거부(403), 운영자 삭제(`ADMIN_TOKEN`), IP당 하루 60회(기존 랭킹 등록과 합산) |

공개 고지는 등록 버튼 바로 위에 보여 주고, `공개에 동의하고 정밀 랭킹 등록` 버튼을 누르는 것을 공개 동의로 본다.

- 등록하면 닉네임, 신고 원산지, 경상 농도, 경북권 비율, 등록 시각이 정밀 감정 랭킹에 공개됩니다.
- 음성과 받아쓰기는 저장하지 않으며, 기록은 대회 종료 후 1주 안에 모두 삭제합니다.
- 부적절한 닉네임은 운영자가 삭제할 수 있습니다.

정밀 랭킹 항목 JSON:

```json
{
  "rank": 1,
  "id": "gr_3f9a0c1b2d4e",
  "nickname": "대구토박이",
  "origin": "daegu",
  "intensity": 69,
  "gyeongbuk": 64,
  "grade": 4,
  "gradeName": "자막 필요",
  "matched": true,
  "registeredAt": "2026-11-23T14:03:00+09:00"
}
```

- `rank`는 조회한 보기 안에서의 순위다. 등록 응답(201)의 `rank`는 전체 순위다.
- `gyeongbuk`은 경북권 비율이고 경남권은 100에서 뺀 값이다. `grade`, `gradeName`, `matched`는 저장하지 않고 읽을 때 붙인다.
- 항목 id는 gr\_ 뒤에 16진수 12자리다. 오류 형식과 상태 코드는 기존 랭킹(7장)과 같다. 신고 원산지나 보기(`area`)가 정해 둔 값이 아니면 400 `invalid_request`다.

### 가짜 응답 모드

`MOCK_AI=true`면 정밀 감정도 경상 전용 가짜 출력(경북권 64, 경남권 36, 농도 69)으로 후처리까지 실행해 흐름이 끝까지 돌아간다. 신고 원산지를 대구나 경북으로 고르면 원산지 일치, 부산, 울산, 경남으로 고르면 불일치가 나온다. 기존 랭킹과 같이 이 모드의 결과는 정밀 감정 랭킹에 등록할 수 없다(403 `not_eligible`, `reason: "mock"`).
